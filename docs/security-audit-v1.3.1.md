# VideoSave v1.3.1 Security & Privacy Final Audit

- **Audit Date**: 2026-11-28
- **Scope**: End-to-end internal engineering security and privacy audit of VideoSave `v1.3.1` across Browser Extension, Local HTTP Companion (`127.0.0.1`), MCP Server (27 tools), CLI, Windows/Unix Installers & Bootstrappers, Supply-Chain Updater, Native Bilibili & Public Platform Adapters, DSH-12 Sandbox Audit, and Standalone Android APK.
- **Disclaimer**: This is an internal engineering audit backed by automated security regression tests and live Android/browser verification — **not** a third-party external penetration-test certification.

## 1. Security Attack Surface Review & Concrete Mitigations

| Attack Surface | Risk Reviewed | Concrete Mitigation & Verification Evidence |
| :--- | :--- | :--- |
| **Android Components & Intents** | Arbitrary background download injection by malicious third-party apps; XXE in DASH MPD; fake XML/HTML saved as `.mp4` | `DownloadService` is strictly `android:exported="false"` (verified live on Android 16 Emulator: external `am start-foreground-service` denied with `Requires permission not exported`). `DashEngine.java` disables DOCTYPE & external entities (`AndroidCoreSelfTest` verifies XXE rejection). `MediaContainerUtil` + `MediaExtractor` verify every output before `MediaStore` export (fake XML-as-MP4 verified rejected live on Android 16). |
| **Component Downloads & Supply Chain** | Tampered runtime binaries (Node.js, FFmpeg, yt-dlp) or untrusted update mirrors | All managed downloads (`start-windows.ps1`, `start-unix.sh`, `setup-platform-downloads.mjs`) verify pinned SHA-256 digests before atomic installation into user-scoped directories. `tools/updater.mjs` strictly enforces `https://github.com/KaiserIIII/videosave/releases/download/` allowlist, verifies `SHA256SUMS.txt`, distinguishes `sigstore-provenance-verified` (`gh attestation verify`) from `sha256-same-channel-only`, backs up `settings.sqlite`, and **never** auto-executes downloaded installers. |
| **Local HTTP Service & `/console`** | Cross-site request forgery (CSRF), clickjacking, DNS rebinding, remote network exposure | Binds strictly to loopback `127.0.0.1` only. Rejects non-loopback `Host` headers (DNS rebinding protection), enforces Bearer pairing code / `HttpOnly; SameSite=Strict` session cookie + explicit CSRF header, sets `Content-Security-Policy` & `X-Frame-Options: DENY`. |
| **MCP Permission Model** | Prompt injection from untrusted webpage titles/descriptions; unauthorized settings/file access | Webpage titles/descriptions are explicitly flagged `untrusted: true`; `update_settings` never accepts page text as authorization; `open_file` strictly validates realpath containment inside `outDir`; managed browser mode requires per-client registration, per-tab/origin approval, and rate limits. |
| **Cross-Origin Cookie & Header Isolation** | Leaking session `Cookie` or `Authorization` headers to third-party CDN hosts or echoing raw cookies to AI | `RequestContext` scopes `Cookie` strictly to exact origin (`*.bilibili.com` API only for Bilibili); `import_cookie_file` holds cookies in memory-only TTL sessions, strips challenge cookies (`challenge-cookie-ignored`), and never echoes raw cookie values to MCP responses or logs. |
| **SSRF & Redirects** | `b23.tv` or media URLs redirecting to loopback, RFC 1918 private LAN, link-local, or cloud metadata endpoints | `resolveBilibiliShortLink` uses `redirect: 'manual'` and requires destination host in `BILIBILI_API_HOSTS`. `isSafeBilibiliMediaUrl` strictly requires `https:` and blocks loopback/RFC 1918/CGNAT/link-local/IPv6 ULA addresses. |
| **Path Traversal, File Overwrite & Symlink/Junction Escape** | Writing outside `outDir` or test sandbox via `..`, symlinks, Windows Junctions, or UNC paths | `assertSandboxPath` + `resolveThroughSymlinks` resolves ancestor symlinks/junctions before any write; `save()` supports atomic `.part` + `uniquify`/`skip`/`overwrite` with sanitized filenames (`CON`/`PRN`/`NUL` Windows reserved device names neutralized). |
| **Command Injection & ReDoS** | Shell metacharacters in URLs/filenames/headers; catastrophic backtracking in custom `idPattern` | All subprocesses (`ffmpeg`, `ffprobe`, `yt-dlp`, `explorer.exe`) execute via `spawn`/`execFile` argument arrays with `shell: false` (never string shell interpolation). `validateSafeIdPattern` rejects nested quantifiers and caps length to 128 chars. |
| **SQLite, Caches & Resource Exhaustion** | DB lock contention, orphaned staging caches, unbounded memory/disk growth | SQLite uses `WAL` + `busy_timeout=5000`; Android `DownloadService` enforces a 50 MB free-space floor, prunes staging caches older than 48h, and cleans caches on cancel/fatal error; Desktop bounds chunk sizes, segment counts, and playlist sizes. |
| **Anti-Bypass & Legal Boundaries** | Circumventing DRM, paywalls, CAPTCHAs, or HTTP 401/403/451/567 | Strictly prohibited across all surfaces. Bilibili official `backup_url` failover applies **only** to standard RFC 5xx/408 transient server failures; HTTP `401/402/403/412/451/567` and API codes `-101/-10403` abort cleanly without rotation or identity spoofing. |

## 2. Privacy Leak Scan & Historical Git Commit Risk Report

- **Current Working Tree (`v1.3.1`), Test Reports, Screenshots & Release Archives**: Scanned via `tools/check_doc_consistency.mjs` for personal usernames, cloud-sync folders, personal download directories, cookies, tokens, and signing keys → **0 leaks detected**.
- **Historical Git Commits Advisory (No History Rewritten)**:
  - Per policy, prior Git commits and published tags (`v0.2.0`–`v1.3.0`) were **not** rewritten or force-pushed.
  - Earlier historical development discussions or pre-`v1.0.0` commits should be audited by the repository owner if full historical scrub is ever desired.
  - **Optional Owner-Controlled Remediation Plan (Only if desired in the future)**:
    1. Run `git log --all -S "<sensitive-string>" --oneline` locally to confirm whether any old commit blob contains unwanted metadata.
    2. If needed and acceptable to break existing clones/tags, use `git filter-repo --replace-text` on a mirror clone and coordinate a fresh tag set — **never** run automatically without explicit owner authorization.
