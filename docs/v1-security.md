# VideoSave 1.0 release candidate security review

## Browser authority and transfer boundary

- The paired extension submits playback evidence. The managed client can request an approval and choose candidate IDs. It cannot submit playback observations or change the allowed origins. Test coverage includes independent standing download consent, caller ownership, tab reload and logout, and revoking paused work.
- Related public HTTPS media requires owner consent and successful playback evidence tied to the approved document and frame. A manifest can reference its own origin. A different origin needs an exact observed resource tied to the same frame and player origin. Redirects require an exact approved target and are capped at three hops.
- For related CDN requests, DNS lookup runs inside the HTTPS connection. Private, loopback, reserved and mixed public/private answers are rejected. The CDN path requires direct routing because the existing proxy cannot enforce this lookup policy. The exact approved site can still be a local host for legitimate local media and fixtures.
- Only sanitized playback Referer, Origin and User-Agent enter the managed transport. The selected direct file may use its same-origin Cookie subject to its domain, path, expiry and Secure rules. Cross-origin and redirect requests do not inherit those cookies. CDN-specific login credentials are unsupported in this candidate.
- Managed candidate, task and approval responses use allowlists. Signed resources are held in the extension's session storage and the companion's in-memory grant. Approval outputs and compatibility reports contain no raw resource evidence. The separate legacy local HTTP and standalone MCP interfaces can still return URLs to their trusted operator.
- An HTTP access denial or a browser challenge stops the managed transfer. A known expired URL requires fresh approved playback. A new signature or additional origin does not silently expand an active job's authorization.

## Media parsing and output

- The DASH parser rejects entity declarations, unsupported structures, oversized manifests and unbounded segment expansions. Track initialization is checked for declared protection before segment transfer. The staged outputs are checked for expected tracks and duration. DRM, denied access or an out-of-scope URL is a terminal outcome.
- Managed FFmpeg operates on companion-generated local staging files with protocol restrictions. File verification resolves the output under the recorded destination and checks it with FFprobe. The release introduces no new executable dependency. Installer sources, commits and checksums remain in the packaged SBOM.
- Strategy imports accept only exact origins and supported strategy values. They cannot execute code. Adaptive probe history contains aggregated outcomes and no media URL, credential, page content or download record.

## v1.0.0 Independent Security & Isolation Audit Additions

- **Unified Request Context & Cross-Origin Credential Isolation (`tools/request-context.mjs`, `tools/media-source.mjs`)**: Explicit `Referer`, `Origin`, and `User-Agent` propagate consistently across master playlists, media playlists, init segments, media segments, byte ranges, separate audio/subtitle tracks, AES-128 keys, retries, checkpoint resumes, authorized refreshes, and FFmpeg fallback. `Cookie` and `Authorization` are strictly scoped to the credential origin and never forwarded cross-origin. FFmpeg fallback uses host+port scoped `-cookies` (`domain=${url.host}`) to prevent cookie drop on non-default ports while preserving origin isolation.
- **Binary Media Content Sniffing (`tools/media-inspector.mjs`)**: Validates container bytes (MPEG-TS, ID3-prefixed TS, M2TS, verified custom-prefixed TS, ISO-BMFF/fMP4, AES-128 post-decrypt plaintext, WebVTT) independent of misleading URL extensions or MIME types, and strictly rejects real PNG/JPEG/GIF/WebP images, HTML/JSON/XML error pages, corrupted payloads, and DRM boxes (`pssh`/`sinf`/`encv`/`enca`/`tenc`).
- **Cookie Store & Secret Redaction (`tools/cookie-store.mjs`)**: Parses Netscape 7-column `cookies.txt` (including `#HttpOnly_`, domain/subdomain, path, `Secure`, expiry) and single-line `Cookie:` headers within a 64 KiB cap; rejects anti-bot challenge cookies (`cf_clearance`, `__cf_bm`); stores imported cookies strictly in memory with bounded TTL (1–120 min) and never echoes raw cookie values to AI tool responses or SQLite.
- **Dedicated Isolated Browser Profiles (`tools/browser-sessions.mjs`, `tools/edge-session.mjs`)**: Supports explicit `profileMode: "dedicated"` + regex-validated `browserSessionId` confined strictly inside `<stateDir>/VideoSave/profiles/` (or `VIDEOSAVE_PROFILES_DIR`). Rejects system browser profile takeover (`profileDir`, `useBrowserCookies: true`), validates `browserBinary` against an allowlist of local Chromium executables, and flushes sessions cleanly via CDP `Browser.close` without stale `DevToolsActivePort` reuse.
- **ReDoS & Path Traversal Prevention (`tools/media-downloads.mjs`)**: Rejects nested-quantifier regex patterns in `probe_page.idPattern`, enforces strict `outDir` confinement on `open_file`, and rejects untrusted `Origin` headers or unauthenticated calls on the loopback companion HTTP server.
- **Mandatory Test Sandbox Isolation (`tests/test-sandbox.mjs`, `tools/preferences.mjs`, `.github/workflows/verify.yml`)**: `getSettingsFile()` and `getDefaultOutDir()` resolve dynamically and enforce `VIDEOSAVE_TEST_SANDBOX` confinement (`TEST_SANDBOX_VIOLATION`). All test suites isolate downloads, SQLite databases, cookies, and browser profiles inside `.ots/tmp/videosave-tests/` and assert zero additions/modifications to real user download folders, backed by a mandatory CI gate.

## Verification scope

The changed paths are exercised by `tests/request-context.test.mjs`, `tests/media-inspector.test.mjs`, `tests/resume-fault-injection.test.mjs`, `tests/probe-browser-options.test.mjs`, `tests/batch-queue-and-quality.test.mjs`, `tests/test-isolation-and-security.test.mjs`, `tests/mcp-control.test.mjs`, `tests/managed-batch-controls.test.mjs`, `tests/mcp-control-browser.test.mjs`, `tests/dash-prefetch.test.mjs`, and `tests/compatibility-policy.test.mjs`. The optional public acceptance run uses official public samples and normal playback. The review does not cover a fresh independent audit of FFmpeg, browser binaries, yt-dlp, or their transitive dependencies.
